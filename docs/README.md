## 维护约定

- 功能、快捷键、存储或构建流程变化时，同步更新对应的当前文档和日期。
- 区分已实现、候选方案和历史决定；不将旧计划写成现状。
- 验证结果带日期和范围，不把一次通过解释为所有系统和目标应用都兼容。
- 以代码和测试为事实依据，避免固定测试文件数量、无边界的性能保证或永久免授权承诺。
- 历史档案保留原文，通过入口说明失效范围，不回写后来的事实。
- 隐私脱敏可以将历史文档中的个人绝对路径改为等价的仓库相对路径，但不改变当时的功能和验收结论。忽略规则不会清理已提交的历史。
