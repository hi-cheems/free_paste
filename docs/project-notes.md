# FreePaste 项目说明

> 最后更新：2026-10-17

## 项目定位

FreePaste 是一个面向普通用户的 macOS 菜单栏剪贴板历史工具，目标是把“复制过的内容再次找到并重新使用”这个动作做得足够快、足够稳定。

当前产品定位：

- 本地优先
- 文本工作流优先，但已经支持图片和文件 URL
- 以菜单栏 + 全局快捷键为主要入口
- 面向开源发布，并保留 App Store 方向

当前迭代意愿：

- 现有功能已经足够日常使用
- 短期不主动推进新的大功能
- 后续以 bug 修复、体验稳定和低风险维护为主
- 新能力需要由真实使用中的明确痛点驱动，而不是为了继续扩展功能而扩展

## 当前能力概览

项目当前已经具备一个完整的本地 MVP：

- 菜单栏常驻入口
- 全局快捷键唤起 / 隐藏面板
- 剪贴板历史自动采集
- 文本、图片、文件 URL 三种内容类型
- 搜索、删除、清空未收藏历史、重新复制
- 全部记录（界面标签“最近”）/ 单一收藏夹
- 收藏 Key 搜索，Key 命中优先于内容命中
- 默认快速搜索 / 详细文本编辑两种搜索模式
- 全文预览
- 面板内键盘导航
- 直接粘贴回原应用
- 历史保留策略
- 黑名单应用
- 暂停记录（手动 / 5 分钟 / 15 分钟）
- 粘贴为纯文本
- 富文本格式保留
- 批量收集、正逆序输出、拖动重排与逐项粘贴
- 历史摘要加载、原始载荷按需读取与图像缩略图缓存
- 开机自启
- 快捷键自定义与冲突检测

## 主要入口与用户工作流

典型流程：

1. 用户在其他应用中复制内容
2. FreePaste 后台监听并保存历史
3. 用户通过菜单栏图标或全局快捷键打开面板
4. 用户搜索、浏览、收藏或预览某一条记录
5. 用户单击选中条目，再双击或用回车确认；右键可预览
6. FreePaste 将内容回写剪贴板
7. 确认流程尝试恢复原应用并发送 `Cmd+V`；`Shift + Return` 对文本使用纯文本粘贴

## 当前实现状态

### 核心层

- `ClipboardMonitor`
  - 轮询系统剪贴板
  - 支持文件 URL / 图片 / 文本三类内容
  - 文本会额外保留富文本原始格式
- `ClipboardHistoryStore`
  - Core Data 持久化
  - 支持收藏 Key、搜索、淘汰和旧模型迁移；加载失败时保留数据库并临时使用内存存储
- `ClipboardManager`
  - 作为 UI 单一数据入口
  - 处理搜索、收藏、回写剪贴板、纯文本粘贴、黑名单过滤、暂停记录

### UI 与平台集成

- `AppDelegate`
  - 管理状态栏、底部悬浮面板、右键菜单、全局热键、设置窗口和 direct paste 流程
- `ClipboardHistoryView`
  - 贴底整宽、约占可用屏幕高度 20% 的横向卡片时间线
  - 全部记录 / 单一收藏夹，支持通过 `Tab` 切换
  - 面板唤起后可直接输入搜索，导航键仍选择记录；`Command + F` 进入详细编辑，`Esc` 返回默认模式
  - 收藏范围沿用默认快速搜索模式；新增收藏需填写 Key，右键可修改 Key
  - 搜索框、键盘导航、内联消息、暂停状态提示
- `ItemPreviewPresenter`
  - 独立预览面板
- `SettingsView`
  - 历史策略、隐私、快捷键、开机自启

## 收藏搜索

- 收藏仍绑定原有历史记录，不引入独立的内容库或 UI。
- 按 `Command + D` 或点击星标新增收藏时，填写 Key 后才保存；取消输入不改变记录。
- 一条收藏使用一个 Key 文本字段，同一个 Key 可以对应多条收藏；已收藏记录按原快捷键取消收藏。
- 右键菜单“设置 Key”可修改或清空 Key，已有收藏的 Key 默认为空。
- 空搜索按记录的 `timestamp` 倒序展示（当前没有独立的收藏时间字段）；非空搜索包含匹配 Key 和内容，忽略大小写，Key 命中排在仅内容命中之前，各组内部保持时间排序，单条记录不重复展示。
- 图片可通过手动设置的 Key 搜索；此功能不进行图片 OCR。
- 默认范围包含普通历史与收藏，也支持收藏 Key；`Tab` 切换到仅收藏范围，保留查询内容。

## 搜索交互

- 面板唤起后使用默认模式，直接输入查询；搜索框不显示闪烁光标，右侧提示“⌘F 编辑”。原生输入框负责文字输入，但方向键和配置的上一项/下一项快捷键操作记录选择，回车粘贴选中内容。
- 按 `Command + F`、配置的搜索快捷键或点击搜索框进入详细模式，恢复编辑光标并隐藏右侧编辑提示；方向键、导航快捷键、Tab、回车、复制、粘贴、撤销等按原生文本编辑处理，不操作记录列表。
- 详细模式只有 `Esc` 返回默认模式，并保留查询内容与有效的记录选择；默认模式的 `Esc` 关闭面板。
- `Tab` 在默认模式切换全部记录与仅收藏范围，不改变搜索模式；没有结果时仍可继续输入。
- 查询变化时优先选中第一条结果；查询清空后恢复该范围的时间排序。
- 普通退格修改查询，删除记录的默认快捷键为 `Command + Backspace`；空格可用于多词查询，预览通过条目右键菜单进入。
- 旧默认 `/` 和裸退格绑定分别一次性迁移为 `Command + F` 和 `Command + Backspace`，其他自定义绑定保持不变。
- 输入法存在未提交的组词内容时，导航键、回车、空格和 Esc 优先交给输入法。
- 搜索列表继续使用轻量摘要，不加载图片和富文本原始数据；收藏 Key 优先级与原始粘贴内容保持不变。

## 批量粘贴

- 在原应用中选中内容，按 `Command + Shift + C`，应用先复制当前选区，再将新内容作为第一项开始收集；不能复制有效选区时不启动，不用旧历史替代。
- 继续复制文本、图片或文件 URL 即可收集。浮窗竖向、置顶，顶部栏可拖动，条数增多时增高，达到上限后滚动。
- 列表按输出顺序展示，默认输出最上方；正序追加、倒序插入头部，切换方向反转当前队列。
- 鼠标拖动或上下方向键可调整条目顺序；显式选中条目优先输出，未选中则取第一项。
- `Command + V`、浮窗内回车、鼠标双击共用逐项输出逻辑，移除输出条目。删除选中项后焦点落到下一项，末尾则落到前一项。
- 最后一项移除后自动结束；关闭按钮放弃剩余队列，`Esc` 只清除显式选择。会话不跨重启恢复。
- 批量活跃期间锁闭原历史和收藏面板入口，需要辅助功能及输入监控授权。
- 临时队列上限为 200 项、256 MiB 估算载荷；文件计 URL 字符串，不计文件本身大小。这不是进程内存上限。
- 黑名单同样适用于批量收集；历史暂停只阻止持久历史，批量仍可收集。正常记录开启时收集内容也会入历史，关闭队列不会删除历史。

## 性能与数据安全

- 启动加载摘要，新增、删除、收藏和淘汰增量更新，避免每次复制重载所有记录。
- 原始图片和富文本按粘贴 / 预览需要读取；列表缩略图最长边 512 像素，预览最长边 1600 像素。
- 图像缓存有数量与成本限制，仍需长期高强度实测，不承诺所有情况下内存不增长。
- 去重仅作用于未收藏的相同文本和相同文件 URL 列表，图片不去重。
- 已知旧模型可迁移；失败时保留原数据库，临时使用内存 Store，而不是删除旧历史。
- 不存储来源应用，不抓取网址预览，不进行 OCR。

## 技术选择

主要栈：

- Swift + SwiftUI
- AppKit
- Carbon `RegisterEventHotKey`
- Core Data
- ApplicationServices / CGEvent

不依赖必需第三方库，当前核心能力都基于系统框架实现。

## 当前短板

目前最明确的功能缺口：

- 图片内容本身不支持 OCR 搜索，但收藏图片可通过 Key 搜索
- 图片不做去重；文件 URL 已支持未收藏记录去重
- 旧历史数据如果没有富文本原始数据，重新粘贴时仍只能作为纯文本

当前最需要继续打磨的方向：

- 真实使用中暴露的焦点、输入法、预览、direct paste 等体验问题
- 现有核心链路的稳定性和可解释性
- 必要时再评估敏感内容过滤、隐私能力细化或图片 OCR 搜索

## 发布与同步判断

当前构建入口为 `./scripts/build-fixed-debug.sh`，同时生成脚本同级的 `FreePaste.app` 和 `FreePaste.dmg`；`package-dmg.sh` 可单独包装已有应用。DMG 内是应用与 Applications 链接，便于拖拽安装，不包含用户历史。

公共工程与脚本不固定开发团队。个人签名团队保存在 Git 忽略的 `FreePaste/Config/Signing.local.xcconfig`，其他开发者从同目录示例创建自己的配置；脚本也支持 `DEVELOPMENT_TEAM` 环境变量。具体步骤和历史隐私边界见 [开发文档](development-workflow.md)。

当前产物是 Apple Development 签名的 Debug、实测架构 arm64，不是已公证的公开发行版。公开分发的签名、公证和验证边界见 [DMG 调研](dmg-packaging-research.md)。

新增 `build-release.sh` 入口，生成单独的 Universal 自用 Release，沿用开发签名，未做公证；原 Debug 入口不变。构建与使用见 [Release 构建](releasing.md)。

发布方向：

- 当前适合继续打磨本地单机体验
- 当前不需要主动扩展功能范围
- 开源方向明确
- App Store 仍是后续可选目标

同步方向：

- 同步层应继续和核心逻辑解耦
- CloudKit 与局域网同步都属于后续能力，不建议当前优先实现
