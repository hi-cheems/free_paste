# 风险与设计决策

> 日期：2026-03-15
> 说明：这是该迭代当时锁定的风险和权衡，不应替代当前项目级架构判断。

## 已锁定的设计决策

### 1. 本次迭代聚焦于纯文本 direct paste

原因：
- 当前产品本身就是 text-first
- 如果同时加入图片或文件支持，会让范围膨胀过快

### 2. `Accessibility` 权限是必须条件

原因：
- 向其他应用直接粘贴属于系统自动化能力
- 如果静默降级为“只复制不粘贴”，功能语义会变得模糊

当前决定的行为：
- 如果权限缺失，触发系统权限申请
- 不伪装成 direct paste 已成功

### 3. direct paste 逻辑不应放在 `ClipboardManager`

原因：
- `ClipboardManager` 属于剪切板领域逻辑
- 应用激活和 `CGEvent` 发送属于平台集成逻辑

### 4. 列表导航不循环

原因：
- 对于短列表和瞬时面板来说，不循环的方向键导航更可预测

## 主要风险

### `NSPopover` 内的焦点管理

风险：
- 键盘事件可能一直停留在搜索框，或者无法顺畅切入列表

缓解方式：
- 明确实现焦点切换规则
- 在做自动化粘贴之前，优先验证搜索框与列表之间的切换

### 应用激活时机

风险：
- 如果过早发送 `Cmd+V`，事件可能打到错误的应用，或者直接丢失

缓解方式：
- 将应用激活和粘贴统一封装到同一个 service
- 必要时允许加入一个很小的可调延迟

### 权限 UX

风险：
- 用户可能拒绝权限，然后误以为功能损坏

缓解方式：
- 显式展示缺权限状态
- 保持行为简单且确定，不做模糊降级

### UI 与自动化逻辑耦合过深

风险：
- 如果 View 直接持有应用激活逻辑，后续维护会更困难

缓解方式：
- View 只负责选择与确认
- 自动化逻辑放入独立 service

## 暂缓处理的问题

以下问题有意延后到核心链路跑通之后再决定：
- 搜索框中的 `Return` 是否始终确认第一条结果
- `popover` 是否需要内联显示权限警告
- 从状态栏图标打开时是否也提供 direct paste
- 再次打开 `popover` 时是否保留上次选中项
